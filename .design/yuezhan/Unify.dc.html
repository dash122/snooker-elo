THE MERGE

空檔同場次唔應該係兩樣嘢

我之前喺 availability_slots 隔籬另起咗一張 night_attendance。但打開個 baseline 一睇，前者本來就已經有開始時間、結束時間、場地同軟刪除——即係話啱嘅形狀一直都喺度，我起咗第二張冇時間、一日一格嘅表擺喺佢隔籬。

而家 · 三樣互不相通嘅嘢
availability_slots 有 start_at / end_at / venue。要人手畫時段，冇人畫，所以係一個冇讀者嘅寫入。
nights + night_attendance 一日一行，冇時間。而且 UNIQUE(night_date) 令全個產品一日得一個場次。
match_invites / offers / open_calls 全部一對一形狀，同上面兩樣冇任何供給關係。
提案 · 一張表
availability_slots
start_at, end_at ← 已經有 cancelled_at ← 已經有 venue_id ← text 改做 FK commitment ← 新：going | interested
一個成員講嘅嘢由頭到尾只有一種：我幾時會喺邊間波房。
場次唔再係一張表，係一個查詢 「今晚 SCAA」＝ 揀出該場地、該日、未取消嘅 slot，再按時間睇重疊。冇 nights 表，就冇一日一個場次嘅限制——一日幾多場，由數據自己講。
同一張表，三種落力程度 — 呢個先係真正嘅協同
1 下 撳「我會去」 寫入一個預設時段（例如今晚 18–22 點）。零決定。但佢寫嘅係一個真正嘅時段，所以佢即刻對其他人有用。
2 下 撳埋一個時段 chip 下午／6 點後／8 點後／10 點後。係修正，唔係問題——你唔撳都已經有嘢寫咗入去。
畫 用返現有嘅時段板 計劃型球友照樣可以拖曳精確時段。同一張表、同一個讀者——佢哋畫嘅嘢終於有人睇。

上一版「公開空檔」係一個冇讀者嘅寫入，所以冇人做。而家最求其嗰一下撳，寫入嘅同計劃型手畫嘅係同一種資料——兩者一齊餵同一個重疊查詢。呢個先係「空檔」同「約局」之間一直欠缺嘅供給關係。

要刪嘅嘢
nights 同 night_attendance 兩張表（連埋嗰個 UNIQUE 限制） lib/nights.ts 大部分：四級把握、加權、Poisson-binomial、衰減、升級 fixpoint db/nights.pg.ts 嘅 calibration 查詢
要加嘅嘢
venues 表（名、地區、檯數）＋ venue_id FK commitment 欄位，預設 going（現有的 slot 全部係 going） 一個純函式：一堆 slot → 逐個鐘嘅重疊 ＋ 最高重疊時段
遷移上要小心嘅一點 現有 availability_slots 仲帶住 posted / fill_rule / filled_by / result 呢套開局卡欄位。呢啲係舊嘅一對一機制，唔應該同 commitment 混淆——要決定係一次過拆走，定係先留住行多一排。呢個係實作前要拍板嘅事。
